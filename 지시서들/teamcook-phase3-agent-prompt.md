# teamcook 3차 개선 — 선택적 로컬 실행·A2A 실습 실행 프롬프트

당신은 teamcook의 기존 코드를 수정하는 코딩 에이전트다. 1·2차 결과를 먼저 점검하고, 사용자가 선택한 로컬 실행과 A2A 입문 실습을 끝까지 구현하라. 계획이나 연결 버튼만 만들고 종료하지 마라.

## 1. 목표와 범위 고정

사용자 흐름은 두 갈래다.

1. 레시피 선택 → 로컬 실행 환경 연결 → 실행 준비 확인 → 사용자가 실행 → 상태·산출물 수집 → 2차 기록·비교에 반영
2. A2A 실습 선택 → 로컬 에이전트 2개 준비 → 기능 소개 확인 → 작업 요청·상태 조회·결과 수신 → 기록 검토

3차 최소 구현은 **CLI 연동 1종과 A2A 로컬 실습 1종**이다. 모든 도구·OS를 지원하는 플랫폼을 만들지 않는다.

포함:

- 사용자가 직접 시작하는 로컬 실행 도우미
- 설치·버전·지원 기능 점검과 관측 범위 표시
- 단일 실행 작업 시작·상태·중지·복구 가능한 기록
- 2차 기록으로 이벤트·결과·측정 연결
- 모델 API 키 없이 가능한 로컬 A2A 프로토콜 실습

제외:

- 클라우드에서 사용자 PC 원격 실행, 공개 실행 서버, 계정·과금 플랫폼
- 범용 DAG·분기 실행 엔진, 자동 모델 선택, 자율 반복 수정
- 여러 CLI의 무제한 자동 연계, 운영용 A2A 디렉터리
- 자동 재시도·자동 재개·자동 덮어쓰기
- 기존 프롬프트 흐름을 강제 실행 규칙으로 자동 승격하는 변경

이번 범위에는 로컬 실행 도우미와 샘플 서버 개발이 포함된다. 코드를 개발·격리 테스트하되, 사용자 계정의 실제 모델 호출·설정 변경·배포는 검증에 필요한 구체적 범위가 허용되었을 때만 수행한다.

## 2. 공통 원칙

- AGENTS.md와 기존 규칙, `teamcook-phase1-agent-prompt.md`, `teamcook-phase2-agent-prompt.md`, 구현 기록을 읽는다.
- 현재 체크아웃·기존 변경·브라우저 데이터·공유 링크·수동 기록을 보존한다.
- 관련 소스가 없으면 정확한 위치를 요청한다. 빈 저장소에 추측한 새 제품을 만들지 않는다.
- 커밋·푸시·외부 배포는 별도 지시 없이는 하지 않는다.
- UI는 한국어로 작성한다. 명령·프로토콜 세부는 필요한 고급 영역에 둔다.
- CLI 옵션·구조화 출력·A2A 규격은 개발 시 최신 공식 문서와 사용 버전을 확인한다. 이 문서의 개념명을 실제 API 이름으로 추측하여 구현하지 않는다.
- 새 의존성은 기존 런타임과 공식 SDK 중심으로 최소화한다.
- 실행·전송 전 사용자가 대상을 이해할 수 있어야 한다. 환경 연결이나 상태 조회만으로 모델 실행을 시작하지 않는다.

## 3. 작업 순서와 완료 기준

### 작업 0 — 1·2차 점검과 기술 경로 확정

점검표에 `통과 / 일부 / 누락 / 회귀 / 미확인`과 코드 위치·검증 결과를 기록한다.

- 1차 데이터 이관·내보내기·권한 표시·지시문/실행 구분
- 2차 스냅샷 독립성·기록 상태·증거 출처·비교 조건
- JSON 가져오기·ID 재매핑·보고서 스냅샷·저장 오류 처리
- 현재 배포·라우팅·빌드 방식과 로컬 실행 가능한 환경

진행 규칙:

- 기록 손실·출처 혼동·중복 실행을 일으킬 선행 결함을 먼저 수정한다.
- 2차 저장 기반 자체가 없으면 선행 작업을 명시하고 종속 구현을 중단한다. 무관한 기존 결함은 별도로 보고한다.
- CLI 후보를 조사해 1종을 선택한다. 지원되는 비대화식 호출·출력·종료·취소 범위를 확인하고 선택 이유를 문서화한다. 미설치 상태도 정상적인 진단 결과로 처리한다.
- A2A는 확인한 공식 규격·SDK 버전을 고정하고 출처·지원 전송 방식·샘플 범위를 기록한다.

**완료 기준:** 실행 경로와 지원 범위를 실제 근거로 결정했다. 브라우저·배포 제약을 가정으로 덮지 않았다. 2차 기록에 연결할 지점이 검증되었다.

### 작업 1 — 로컬 실행 도우미와 연결 방식

기본 실행 모드는 사용자가 명령 한 번으로 켜는 로컬 도우미다. 도우미가 teamcook의 로컬 UI와 실행 API를 **같은 로컬 출처**에서 제공하는 경로를 우선 구현한다. 기존 사이트의 클라우드 배포는 로컬 모드 안내·레시피 내보내기를 유지한다.

이유: HTTPS 사이트에서 임의의 로컬 HTTP 도우미를 직접 호출할 수 있다고 가정하지 않는다. 다른 구조를 선택하려면 지원 브라우저에서 연결·인증·취소까지 검증하고 문서화해야 한다.

최소 동작:

- 명시적으로 시작·종료하는 서비스, loopback 주소로만 수신
- 서버 시작마다 새로 생성되는 세션 접근 정보와 브라우저 세션 연결
- 허용 출처·Host 검사, 상태 변경 요청의 요청 위조 방지
- 실행 작업·산출물에 접근할 때도 연결 세션 확인
- 접근 정보는 레시피·공유 링크·실습 내보내기·일반 로그에 포함하지 않음
- 연결 해제와 인증 만료 처리, 재시작 시 이전 세션 재사용 금지
- 외부 출처·임의 네트워크 인터페이스 공개·광범위 CORS 허용 금지

로컬 모드의 저장소는 클라우드 사이트와 출처가 달라 자동 공유되지 않을 수 있다. 1·2차 JSON 가져오기·내보내기를 활용한 이동 경로를 제공하고 자동 동기화로 표현하지 않는다.

**완료 기준:** 사용자가 켜고 끌 수 있다. 로컬 UI에서 인증된 연결을 확인했다. 외부 출처의 실행 요청이 거절된다. 클라우드 UI에서 연결 가능성을 허위 표시하지 않는다.

### 작업 2 — 환경 점검과 실행 준비 화면

새 ‘로컬 실행’ 화면을 제공한다.

표시 항목:

- 도우미 연결 여부와 확인 시각
- 실제 관측한 OS·CLI 경로/버전·지원 기능
- 로그인 여부는 확인 가능한 경우에만 표시. 비밀 값은 수집하지 않음
- 선택한 프로젝트 경로와 허용 범위
- 레시피 스냅샷·입력·실행 대상·출력 위치
- 적용할 파일·명령의 의미·권한·실행 한도

명령은 서버의 허용된 어댑터에서 구성한다. UI에서 임의 셸 명령을 전달받아 실행하지 않는다. 프로젝트 경로는 도우미에서 실제 경로로 정규화하고 심볼릭 링크·상위 경로 이탈을 검사한다. 선택·허용하지 않은 경로에 쓰지 않는다.

기본은 격리된 실습 폴더다. 기존 프로젝트를 사용하는 경우 파일 변경 계획을 먼저 보여주고 기존 설정을 무단 덮어쓰지 않는다. 단순 지시문 제한을 실행 권한 강제로 표시하지 않는다.

**완료 기준:** CLI 미설치·로그인 미확인·잘못된 경로가 처리된다. 점검만으로 모델 호출이 발생하지 않는다. 실행 직전의 대상·전송 입력·변경 범위가 명확하다.

### 작업 3 — 최소 실행 작업과 상태·취소

선택한 CLI 어댑터 1종으로 한 작업을 실행한다. 초기에는 도우미당 동시 실행 1개로 제한해도 된다. 동시 제한을 UI에 표시한다.

프로세스 상태는 `준비 / 실행 중 / 취소 요청 / 성공 / 실패 / 취소 / 상태 미확인`을 구분한다. CLI의 작업 성공은 실습 평가 성공과 다른 개념이다.

구현 요구:

- shell 문자열 결합 대신 실행 파일과 인수 배열 사용
- 중복 클릭·네트워크 재전송을 같은 요청 ID로 처리하고 같은 작업을 두 번 시작하지 않음
- 시작된 작업 ID와 상태를 지속 저장하고 마지막 이벤트 이후부터 재조회 가능
- stdout·stderr·종료 코드·시간 초과·출력 제한 처리
- 도구가 제공하는 구조화 출력 사용, 일반 텍스트의 추측 파싱은 추정으로 표시
- 사용자 중지 시 지원 OS에서 자식 프로세스까지 중단·확인
- 중지 확인 전에는 ‘취소됨’으로 단정하지 않음
- 브라우저 이탈은 작업 종료와 구분; 재연결 시 상태 복원
- 도우미 비정상 종료 후 기존 실행을 자동 재실행하지 않음. 확인 불가능하면 상태 미확인으로 남기고 수동 정리를 안내
- 시간·출력·지원되는 사용량 한도를 설정하고, 강제할 수 없는 한도는 참고값으로 표시

완료를 확인할 수 없는 작업이 있을 때 새 실행을 무조건 허용해 중복 비용을 만들지 마라. 충돌 여부를 확인하거나 사용자에게 미확인 작업을 명시적으로 처리하게 한다.

실제 서브에이전트 이벤트를 CLI가 노출하지 않으면 관측 범위를 ‘CLI 작업 단위’로 표시한다. 팀원 메시지나 역할 수행을 만들어내지 않는다.

**완료 기준:** 시작·성공·실패·중지·중복 요청·재연결·도우미 종료 시나리오가 동작한다. 프로세스 종료를 결과 정확성으로 표시하지 않는다.

### 작업 4 — 2차 실습 기록과 이벤트 연결

새 실행은 당시 레시피·입력·환경 스냅샷을 가진 2차 기록과 연결한다. 프로세스 상태와 사용자가 관리하는 기록 상태를 분리한다.

이벤트의 최소 개념:

| 항목 | 의미 |
| --- | --- |
| eventId / jobId | 중복 처리와 실행 연결 |
| sequence / observedAt | 순서와 관측 시각 |
| source | 로컬 어댑터·사용자 보고·A2A 샘플 등 |
| type | 시작·출력·상태·산출물·측정·오류 |
| payload | 크기 제한된 내용 또는 산출물 참조 |
| observationScope | 작업 단위·역할 단위 등 실제 범위 |

요구사항:

- 같은 이벤트 재수신 시 중복 기록하지 않는다. 수동 메모를 덮어쓰지 않는다.
- 사용자 입력과 도우미 관측을 출처로 구분한다. JSON 가져오기는 과거 출처 주장을 보존하되 현재 세션이 검증한 기록처럼 신뢰를 승격하지 않는다.
- 역할 ID를 확실히 알 수 없으면 미확인으로 보존한다.
- 측정은 실제 제공된 값·단위·범위만 반영한다. 구독 사용량의 금액을 임의 환산하지 않는다.
- 산출물은 허용된 작업 폴더 내부만 읽고 참조한다. 모델이 출력한 임의 경로·URL을 자동 수집하지 않는다.
- 로그·산출물 가져오기와 내보내기에는 포함 범위를 보여주고, 접근 정보·자격 증명은 저장·내보내기에서 제외한다.
- 수집된 텍스트는 데이터로 렌더링한다. 코드·명령을 자동 실행하거나 후속 작업 지시로 취급하지 않는다.

**완료 기준:** 실제 관측된 상태·결과가 2차 화면과 보고서에 반영된다. 중복·미확인·사용자 메모가 올바르게 처리된다. 자동 관측이 평가 점수를 자동 생성하지 않는다.

### 작업 5 — A2A 입문 실습: 로컬 에이전트 2개

공식 SDK와 고정한 규격을 사용해 **별도의 로컬 에이전트 서비스 2개**를 구현한다. 두 서비스를 한 번에 준비하는 개발 명령과 정리 명령을 제공한다.

기본 예제는 모델 없이 결정적인 샘플 데이터를 사용한다.

- 에이전트 A: 주제 검토 요청을 받아 에이전트 B에 데이터 가용성 확인을 위임하고 결과를 통합
- 에이전트 B: 준비된 GraphRAG 주제 데이터의 가용성·제약을 반환
- 실습 UI: A에 요청하고 작업 상태와 최종 산출물을 보여줌

Agent Card·메시지·작업·산출물의 실제 필드·상태·검색 경로는 선택한 규격에 따른다. 지원하지 않는 상태나 필드를 임의로 추가하지 않는다.

최소 실습 범위:

1. 각 서비스의 Agent Card를 조회하고 역할·기능·주소를 표시
2. 실제 A2A 요청으로 A → B 위임 확인
3. 진행 중 상태를 관찰할 수 있는 비동기 작업과 상태 조회
4. 실제 작업 ID로 최종 산출물 수신
5. 서비스 미실행·타임아웃·유효하지 않은 요청·중복 이벤트 처리
6. 선택한 규격·SDK가 지원하는 취소 범위를 확인하고 반영; 미지원이면 명시

스트리밍·푸시 알림·외부 서비스 검색은 이번 필수 범위가 아니다. 상태 조회 방식으로 완료해도 된다. A2A 프로토콜은 실제로 교환하되 업무 데이터는 샘플임을 모든 화면과 보고서에 표시한다.

샘플 서비스 주소만 허용하는 기본 경로로 구현한다. 임의 외부 URL 입력·자동 스캔·Agent Card에 적힌 주소 무조건 호출은 허용하지 않는다. 소개서 내용과 원격 응답은 신뢰하지 않는 데이터로 취급한다.

Agent Card는 레시피 역할 카드와 별도 모델이다. 레시피를 불러왔다고 A2A 서비스가 자동 생성되었다고 표시하지 않는다.

**완료 기준:** 두 실제 로컬 서비스 사이에서 표준 요청·상태·산출물 교환이 발생하고 테스트로 확인된다. 사용자 키·모델 호출 없이 재현된다. 프로토콜 실습 성공을 실제 데이터 조사 성공으로 표현하지 않는다.

### 작업 6 — 연결 해제·오류 복구·사용자 안내

- 클라우드 모드·로컬 실행 모드·A2A 샘플 모드의 차이와 데이터 이동을 안내한다.
- 연결 끊김, 도우미 미실행, 지원하지 않는 버전, 인증 만료, 취소 미확인에 대한 다음 행동을 제공한다.
- 상태 미확인 작업은 재실행 전 확인하게 하고 자동 재시도하지 않는다.
- 실행을 멈추는 것과 도우미를 끄는 것, 기록을 보관하는 것을 구분한다.
- 지원 OS와 확인한 브라우저·CLI·SDK 버전을 문서화한다. Windows PowerShell에서 개발자가 재현할 시작·실행·중지 절차를 제공한다. 다른 OS는 확인한 범위만 지원 표시한다.
- 로컬 실행을 쓰지 않아도 기존 파일 내보내기·수동 실습 기록·비교 기능을 계속 사용할 수 있게 한다.

**완료 기준:** 연결 실패가 막다른 화면으로 끝나지 않는다. 자동 실행 없이도 기존 제품 흐름이 유지된다. 지원하지 않는 환경의 상태가 명확하다.

### 작업 7 — 통합 검증과 제출

자동 테스트는 가짜 CLI 실행 파일·격리 임시 폴더·실제 로컬 A2A 샘플 서버를 사용한다. 모델 비용 없이 성공·실패·시간 초과·취소·재연결을 재현한다. 실제 CLI 라이브 테스트는 이와 구분한다.

필수 검증:

1. 1·2차 데이터·내보내기·수동 기록·평가·보고서 회귀
2. 연결 인증·만료·외부 출처 거절·경로 이탈 거절
3. 임의 명령 주입 차단·기존 파일 무단 변경 방지
4. 중복 시작 억제·이벤트 재전송 중복 억제
5. 종료 코드·출력 제한·시간 초과·자식 프로세스 중지
6. 브라우저 재연결·도우미 비정상 종료 후 상태 미확인 처리
7. 작업·산출물 접근 제한과 내보내기 비밀 값 제외
8. 단위·관측 범위·출처 보존, 평가 자동 생성 없음
9. 실제 A2A 샘플 2개 사이의 위임·진행 상태·최종 산출물
10. 샘플 오류·취소 지원 범위·서비스 종료 후 정리
11. 키보드·긴 출력·좁은 화면·오류 안내

최종 사용자 흐름 A:

> 로컬 도우미 시작 → 레시피 가져오기 → 환경 점검 → 프로젝트·입력 확인 → 실행 → 상태 확인 → 결과를 2차 기록에 연결 → 수동 기준 기록과 비교 → 보고서 다운로드

최종 사용자 흐름 B:

> A2A 샘플 시작 → 두 소개서 확인 → 주제 요청 → A가 B에 위임 → 상태 조회 → 산출물 확인 → 프로토콜 실습 기록 다운로드 → 샘플 종료

**완료 기준:** 두 흐름이 로컬에서 재현된다. 실제 CLI 호출을 수행하지 못한 경우 ‘가짜 CLI 통합 검증 완료·라이브 미검증’으로 정확히 구분하고 완전한 라이브 지원 완료로 보고하지 않는다. A2A는 실제 샘플 서버 간 교환으로 검증한다.

## 4. 최종 보고 형식

1. 1·2차 점검 결과와 선행 수정 사항
2. 선택한 CLI·A2A 규격·SDK·문서 근거·검증 버전
3. 로컬 모드 시작·중지·레시피 이동 절차
4. 구현 화면·주요 파일·데이터 변화
5. 자동 테스트·실제 서버 통합·라이브 CLI 검증을 구분한 결과
6. 대표 화면과 두 재현 시나리오
7. 관측하지 못한 정보·미지원 환경·남은 제한

범위가 충족되면 종료하라. 운영 배포·외부 에이전트 연결·다중 도구 확장은 별도 작업이다.
