# teamcook 2차 개선 — 실습 기록·비교 평가 실행 프롬프트

당신은 teamcook의 기존 코드를 수정하는 코딩 에이전트다. 먼저 1차 구현 결과를 실제 코드·데이터·화면·테스트로 점검하고, 이후 실습 기록과 비교 평가 기능을 구현하라. 계획서만 작성하고 종료하지 마라.

## 1. 목표와 범위

> 레시피 선택 → 실습 기록 준비 → 외부에서 실습 → 결과·협업 근거 기록 → 동일 과제의 다른 실행과 비교 → 보고서 내보내기

1차가 ‘실습 준비’를 완성했다면 2차는 ‘무슨 일이 있었고 무엇이 좋아졌는가’를 확인하게 한다.

이번에 포함:

- 1차 구현 점검과 2차를 막는 결함 보완
- 로컬 실습 기록 생성·수정·목록·상세·보관·복원
- 레시피·입력·평가 기준의 실행 당시 스냅샷
- 수동 결과·출처·협업 사건·사용자 개입·시간·사용량 입력
- 명시적인 출처를 가진 평가와 동일 과제 비교
- 기록 JSON 가져오기·내보내기와 Markdown 비교 보고서

이번에 제외:

- CLI·모델 직접 실행, 실행 로그 자동 수집
- AI가 자동으로 점수를 매기는 기능과 자동 승자 판정
- A2A·서버 저장·회원 가입·동기화·비용 청구
- 운영용 추적 플랫폼, 범용 워크플로 엔진

기록은 실제로 실행되었다는 인증서가 아니다. 사용자 작성·가져온 자료·자동 관측·확인 불가를 구분한다. 2차의 기본 기록 출처는 사용자 입력이다.

## 2. 작업 원칙

- AGENTS.md, 기존 개발 규칙, 현재 변경 사항부터 확인하라. 현재 체크아웃과 기존 기술·디자인을 재사용하라.
- 같은 위치의 `teamcook-phase1-agent-prompt.md`와 기존 1차 구현 기록을 읽어라. 없으면 실제 코드를 기준으로 점검하고 문서 부재를 기록하라.
- 소스가 없으면 관련 위치를 확인하고 저장소 위치를 요청하라. 다른 폴더에 임의로 복제 구현하지 마라.
- 계획·타입·빈 화면만 만들지 말고 저장과 보고서까지 연결하라.
- 정상적인 구현 판단은 자율적으로 처리한다. 커밋·푸시·배포·사용자 데이터 삭제는 별도 지시 없이 수행하지 않는다.
- 도구별 기술 동작을 변경할 때는 구현과 최신 공식 자료를 확인한다. 지원되지 않는 자동 관측을 흉내 내지 않는다.
- 한국어 UI와 기존 카드·색상·탐색 체계를 유지한다. 1차 내보내기 흐름을 바꾸어 실습 기록 작성을 강제하지 않는다.

## 3. 순서별 작업과 완료 기준

### 작업 0 — 1차 결과 점검과 진행 조건 판정

요구사항을 아래 상태로 분류한 짧은 점검 문서를 기존 문서 위치에 작성하라.

`통과 / 일부 구현 / 누락 / 회귀 / 환경상 확인 불가`

항목마다 코드 위치·검증 방법·결과·2차 영향·조치 여부를 기록한다.

필수 점검:

1. 기존 데이터·공유 링크·가져오기 호환성과 안정적인 ID
2. 학습 목표·성공 조건·역할별 산출물·완료 기준 저장
3. 전달 정보 참조와 카드·산출물 변경 처리
4. 사용자 지시문 보존과 생성 지시문 반영
5. 실행 반영 범위·권한 제한 방식·확인 기록 표시
6. 내보내기 차단 규칙, 최신 미리보기와 ZIP 일치
7. 협업 방식별 시작 안내·GraphRAG 예제·회귀 검사

**진행 규칙**

- 기록·스냅샷·데이터 보존을 막는 결함은 먼저 수정하고 관련 검증을 통과시킨다.
- 국소적인 1차 누락은 연관 범위에서 보완한다. 2차와 무관한 전면 재작성은 하지 않는다.
- 1차 기반 자체가 없거나 데이터 손실 없이 진행할 수 없으면 점검 결과와 필요한 선행 작업을 보고하고 그 의존 작업만 중단한다. 가짜 완성 상태로 2차를 쌓지 않는다.
- 비차단 결함과 환경상 미확인은 남겨 두되 최종 보고서에 명시한다. 점검표 전체가 녹색이어야만 진행한다는 불필요한 조건은 두지 않는다.

**완료 기준:** 통과한 부분과 실제 미구현 부분을 구분했다. 2차에 필요한 저장·식별·스냅샷 기반이 검증되었다.

### 작업 1 — 실습 기록 모델·저장·이관

기존 저장소와 충돌하지 않는 별도 기록 저장 단위를 추가한다. 실행 결과를 원본 레시피에 붙이지 않는다. 작은 텍스트 중심으로 시작하고 파일 자체의 대용량 저장은 도입하지 않는다.

| 대상 | 필수 개념 |
| --- | --- |
| 비교 과제 | ID, 제목, 공통 입력 원문, 첨부 자료 설명·출처, 평가 기준 버전 |
| 실습 기록 | ID, 데이터 버전, 제목, 생성·수정 시각, 비교 과제 ID(선택), 기록 상태 |
| 레시피 스냅샷 | 원본 ID·버전(있으면), 당시 전체 정의, 협업 방식, 역할·산출물·연결 |
| 실행 입력 | 당시 입력 원문, 자료 조건, 환경·도구·모델·버전(모르면 미확인) |
| 결과 | 요약·결과 본문·근거 출처·성공 조건별 확인 상태 |
| 협업 사건 | ID, 유형, 관련 역할, 설명, 증거 참조, 출처, 시간(선택) |
| 평가 | 기준 ID·버전, 판단·점수, 근거, 평가자, 평가 시각 |
| 측정 | 지표명, 값 또는 미확인, 단위, 범위, 출처 |

기록 상태는 `준비 / 기록 중 / 완료 / 중단`을 제공한다. ‘기록 중’은 AI 프로세스 실행 중이라는 뜻이 아니다. 보관 여부는 별도 상태로 둔다.

스냅샷 규칙:

- 생성 시 레시피를 깊은 복사하여 저장한다. 원본 편집·삭제가 과거 기록을 바꾸지 않는다.
- 실제 실습을 기록하기 시작한 뒤 과제·레시피·평가 기준을 바꾸려면 새 기록을 파생 생성한다. 정정 메모는 허용한다.
- 결과·평가의 정정은 수정 시각·수정 이유를 남긴다. 전체 버전 관리 시스템은 만들지 않는다.
- 원본이 삭제되어도 스냅샷과 보고서는 계속 열린다.
- 시간은 시간대가 있는 형식으로 저장하고 UI에서는 사용자 지역 시간으로 표시한다.

저장 오류·용량 초과 시 성공 메시지를 표시하지 않는다. 기존 기록을 보존하고 JSON 다운로드 등 복구 수단을 제공한다.

**완료 기준:** 레시피 변경·삭제 후에도 기록 재열람 가능. 재시작 후 보존. 이관 반복에 중복·손실 없음. 상태와 보관을 구분.

### 작업 2 — 실습 기록 진입·생성·목록

- 레시피 상세에 ‘실습 기록 만들기’를 추가한다. 외부 실행 버튼처럼 보이지 않게 한다.
- 공통 메뉴에 ‘실습 기록’을 추가한다. 목록에서 상태·협업 방식·비교 과제로 필터링한다.
- 생성 화면: 레시피 요약 → 입력 과제 → 환경 정보 → 평가 기준 → 기록 생성.
- 입력 과제 예시는 제안으로 채울 수 있지만 사용자가 실제 입력을 확인하게 한다.
- 같은 과제로 다시 기록하기는 입력·기준을 재사용하고 새 기록 ID를 부여한다. 결과와 점수는 복사하지 않는다.
- 단일 AI 기준 기록은 레시피 없이도 생성 가능하게 한다. 실행 유형을 ‘단일 AI’로 명시하고 도구·모델·실제 프롬프트를 기록한다.
- 빈 목록에는 GraphRAG 실습 경로를 안내한다. 예제 데이터는 명시적으로 불러오게 하고 실제 기록과 구분한다.
- 삭제 대신 우선 보관·복원을 제공한다. 비교 보고서에 포함된 기록의 원본이 보관되어도 보고서를 깨뜨리지 않는다.

**완료 기준:** 레시피 기반·단일 AI 기록을 생성·보관·복원·재열람할 수 있다. 기록 생성만으로 실행 성공 표시가 생기지 않는다.

### 작업 3 — 결과와 협업 근거 편집·상세

상세를 `당시 설계 / 실제 결과 / 협업 근거 / 평가 / 시간·사용량`으로 구성한다. 탭·섹션은 기존 UI에 맞게 결정한다.

결과 입력:

- 결과 본문, 핵심 요약, 근거 출처 목록
- 레시피 성공 조건별 `충족 / 일부 충족 / 미충족 / 확인 불가`와 근거
- 실제 참여 역할, 예정과 달랐던 수행 내용, 미해결 사항

협업 사건 유형:

- 메시지·질문, 이견, 재조사, 판단 변경, 사용자 개입
- 누가 누구에게 무엇을 전달했는지, 어떤 근거가 추가됐는지, 결과가 어떻게 달라졌는지
- 짧은 발췌·출처 URL·사용자 메모 등 증거 참조

표시 규칙:

- 근거가 없는 사건은 ‘사용자 보고, 증거 미첨부’로 표시한다.
- 메시지가 있다는 사실과 협업이 효과적이었다는 판단을 분리한다.
- 예측한 흐름과 기록된 사건을 비교하되, 로그가 없다는 이유로 미실행을 단정하지 않는다.
- 임의 JSON이나 붙여넣은 텍스트가 출처를 ‘자동 검증’으로 바꿀 수 없게 한다.
- Markdown·URL·붙여넣기는 안전하게 렌더링하고 HTML 실행·자동 링크 방문을 하지 않는다.

**완료 기준:** 이견 → 재조사 → 판단 변경을 근거와 함께 기록 가능. 미확인은 실패와 구분. 기록만으로 레시피의 ‘실제 실행 확인’ 표시를 자동 변경하지 않는다.

### 작업 4 — 평가 기준·측정 규칙

공통 기본 기준을 제공한다: 근거 정확성, 조사 범위, 완료 기준 충족, 협업 기여. 프로젝트별 기준 추가·제외가 가능하다.

- 기본 척도는 0~3과 ‘확인 불가’. 기준마다 0·1·2·3의 설명을 제공한다.
- 예: 근거 정확성은 ‘명확한 오류 확인 / 주요 주장 일부만 뒷받침 / 주요 주장은 확인되지만 일부 누락 / 주요 주장이 출처와 일치하고 불확실성을 구분’으로 구체화한다.
- 점수에는 평가자·근거·시각을 남긴다. 출처가 붙었다는 이유만으로 정확성 만점을 주지 않는다.
- 단일 AI의 협업 기여는 ‘해당 없음’이다. 0점으로 합산하지 않는다.
- 기본 화면은 항목별 비교다. 단일 종합점수·자동 승자는 제공하지 않는다.

측정 규칙:

- 시간·토큰·금액은 선택 입력이며 `미확인`을 0으로 바꾸지 않는다.
- 값은 유효한 0과 누락을 구분하고 음수·잘못된 단위·종료 이전 시작 오류 등을 검증한다.
- 전체 경과 시간과 작업자 시간 합계를 구분한다. 병렬 작업 시간의 합을 경과 시간으로 표시하지 않는다.
- 토큰은 도구·모델별 입력/출력·기타 집계 범위를 보존한다. 서로 다른 정의를 같은 값으로 취급하지 않는다.
- 금액은 통화·범위·출처를 기록한다. 구독 사용량을 임의의 API 가격으로 환산하지 않는다.

**완료 기준:** 확인 불가·해당 없음·0점이 구분된다. 평가 기준 스냅샷이 보존된다. 시간·사용량을 근거 없이 계산하지 않는다.

### 작업 5 — 비교 과제와 비교 화면

‘비교에 추가’에서 2~4개 기록을 선택한다. 4개 초과는 추가 비교 묶음으로 안내한다.

화면 순서:

1. 공통 과제와 비교 조건
2. 각 기록의 방식·입력·레시피·도구·모델·환경
3. 결과·성공 조건·항목별 평가
4. 협업 근거와 판단 변경
5. 시간·사용량·사용자 개입
6. 사용자가 작성하는 비교 결론·한계

공통 과제 ID만으로 동일 조건이라고 판정하지 않는다. 실제 입력·자료 조건·평가 기준을 비교한다. 모델·도구 등 차이는 선택한 실험 변수로 표시할 수 있지만 그 차이가 없어지지는 않는다.

- 불일치 또는 확인 불가 조건은 상단에 표시한다. 탐색용 비교는 허용하되 ‘동일 조건 비교’로 표시하지 않는다.
- 점수 기준·척도가 다르면 나란히 원문을 보여주되 증감·순위·합산을 하지 않는다.
- 한 번의 결과를 일반적인 성능 우위로 해석하지 않도록 비교 기록 수와 조건을 함께 표시한다.
- ‘협업 때문에 좋아졌다’는 결론은 사용자 판단과 근거로 남긴다. 자동 인과 추론을 하지 않는다.
- 결론 저장 시 선택한 결과·평가·조건을 스냅샷으로 보존한다. 이후 원본 수정 시 저장 보고서가 조용히 변하지 않는다. 최신 값으로 갱신은 명시적 동작으로 제공한다.

**완료 기준:** 단일 AI·서브에이전트·팀 방식 비교 가능. 조건 차이·미측정이 숨겨지지 않는다. 수정 전 저장 보고서 재현 가능.

### 작업 6 — 가져오기·보고서·GraphRAG 예제

- 실습 기록과 비교 묶음을 버전 있는 JSON으로 내보낸다. 필요한 스냅샷·평가·근거·출처를 포함한다.
- 비교 보고서는 Markdown으로 제공한다: 과제·조건·결과·평가·근거·측정·결론·한계.
- 가져오기는 미리보기·검증 후 별도 저장한다. 기존 ID 충돌 시 기본은 새 ID로 복사하고 내부 참조를 일괄 재매핑한다.
- 잘못된 참조·지원하지 않는 버전·과도한 입력은 부분 덮어쓰기 없이 오류를 안내한다. 파일 크기 제한은 기존 저장 방식에 맞춰 정하고 표시한다.
- 외부로 내보내기 전에 포함할 결과·발췌·환경 정보를 확인할 수 있게 한다.
- 실습 기록은 기존 레시피 공유 링크에 자동 포함하지 않는다. 새로운 공개 업로드 기능은 만들지 않는다.

GraphRAG 데모는 같은 과제에 대한 단일 AI·서브에이전트·팀 방식 3개를 제공한다. 실제 수행하지 않은 결과는 ‘합성 데모’로 표시한다. 한 기록의 일부 사용량을 미확인으로 두고, 이견·재조사·조건 차이 사례를 포함한다. 데모를 실제 성능 비교 근거로 제시하지 않는다.

**완료 기준:** JSON 왕복에서 내용·참조 보존. 가져오기로 기존 기록이 손상되지 않음. Markdown만으로 비교 조건과 한계를 이해할 수 있음. 데모 표시가 보고서에도 유지됨.

### 작업 7 — 검증·1차 회귀·최종 보고

실제 변경과 관련된 테스트를 작성하고 저장소 필수 검사·빌드를 실행한다.

필수 검증:

1. 1차 저장·공유·미리보기·ZIP·토론형·혼합 도구 회귀
2. 레시피 변경·삭제와 기록 스냅샷 독립성
3. 준비·기록 중·완료·중단·보관·복원과 재시작 후 보존
4. 0·누락·확인 불가·해당 없음 구분과 시간·단위 검증
5. 입력·기준이 다른 기록의 경고와 비교 계산 억제
6. 협업 사건 출처·증거 미첨부 표시, 외부 자료의 신뢰 승격 방지
7. 보고서 저장 후 원본 변경과 명시적 갱신
8. JSON ID 충돌·참조 재매핑·오류 시 기존 데이터 보존
9. 저장 실패·긴 텍스트·악성 Markdown·키보드·좁은 화면

브라우저 사용이 가능하면 아래 흐름을 직접 확인한다.

> GraphRAG 레시피로 기록 생성 → 외부 실습 결과를 수동 입력 → 이견·재조사 근거 추가 → 같은 입력의 단일 AI 기록 생성 → 항목별 평가 → 비교 조건 확인 → 보고서 저장·다운로드 → 원본 레시피 수정 후 과거 기록 재확인

**최종 완료 기준:** 위 흐름이 연결되고 1차 기능이 유지된다. 실행하지 않은 실습과 검증하지 않은 주장은 구분해 보고한다.

## 4. 3차 연결 준비

이번에는 자동 실행 없이 다음 경계만 마련한다.

- 기록·증거의 출처와 측정 범위를 명시적으로 저장
- 사용자 메모와 향후 자동 실행 이벤트를 구분할 수 있는 ID·참조 구조
- 수동 기록의 ‘기록 상태’와 향후 실행 작업의 ‘프로세스 상태’를 분리
- 로컬 저장 API를 UI와 분리하되 서버·메시지 큐·범용 플러그인 체계는 만들지 않음
- 보고서 계산이 특정 CLI 로그 형식에 의존하지 않도록 유지

3차 지시서는 `teamcook-phase3-agent-prompt.md`다. 별도 요청 전에는 3차를 구현하지 마라.
