> 작성: 2026-11-24. 조사 대상은 오픈소스 프로젝트 `pingdotgg/t3code`(MIT)이다.
> 이 보고서는 **teamcook 사용자(앱·웹 개발 경력이 거의 없는 제품 결정자)가 읽는 용도**다. 결정은 맨 아래 '정해야 할 것'에 모았다.

> **진행 상황 (2026-11-24):** 4장의 1~4번을 구현했다 — 1) `npx teamcook open` 준비(공개는 사용자 결정), 2) 권한 점검, 3) 측정한 사용량 요약, 4) 위임 계보. 5~6번(프로젝트 고정, 끝났을 때 알림)과 7장의 미확인 항목은 아직이다. 자세한 기록은 `HANDOFF.md`의 '활동 요약·권한 점검·위임 계보', 'npx 배포 준비'.

## 1. T3 Code는 무엇인가

공식 한 줄: **"The open-source control plane for coding agents."** 내 컴퓨터에서 도는 서버가 Claude Code·Codex 같은 **코딩 에이전트를 실제로 실행하고**, 하나의 화면(데스크톱·웹·휴대폰)으로 보여 준다.

- 토큰을 팔지 않는다. 이미 로그인된 구독을 그대로 쓴다. ("does not resell tokens. It drives the agents you are already signed in to.")
- 지원하는 에이전트(README): Claude Code, Codex, Cursor, OpenCode, Grok Build, Antigravity, Kiro, Pi, Muse Code, fx, 그리고 ACP를 쓰는 모든 에이전트.
- 구조(제3자 글): 내 컴퓨터에 서버가 하나 있고, 그 서버가 각 도구를 직접 띄우고 git·터미널을 다루며, 모든 화면이 같은 서버를 본다. 도구마다 연결 방식이 다르다(Claude Code는 Agent SDK, Codex는 app-server 프로토콜 등).

**teamcook과의 근본 차이:** T3 Code는 **실행하는 쪽**, teamcook은 **실행은 남에게 맡기고 팀을 보고 고치고 보고받는 쪽**이다. 그래서 같은 사용자가 둘을 함께 쓸 수도 있다.

### 2-6. T3 Code 스스로 밝힌 한계 (제3자 글)
- 노트북을 닫으면 서버가 멈춘다. 호스팅 서비스가 아니다.
- worktree는 파일·브랜치만 나눈다. 포트·DB·Docker 이름은 안 나눠 충돌할 수 있다.
- 서버를 다시 시작하면 돌던 에이전트가 끊긴다.
- 상당수 기능이 베타·Labs다. README도 "아직 아주 초기"라고 밝힌다.

## 3. teamcook과 겹치는 곳, 겹치지 않는 곳

| teamcook의 중심 | T3 Code에서 확인된 것 |
|---|---|
| 숨김 폴더의 **역할 파일(.claude/agents, .codex/agents)을 팀원 카드로 보이게, 고치게** | **자료에서 확인하지 못했다.** 목차에 프로젝트 설정·t3.json이 있으나 역할 파일 편집은 언급이 없다. (없다고 단정하지는 않는다) |
| **업무 일지**: 어느 도구로 실행했든 기록 파일에서 읽어 보여 줌 | T3 Code는 **자기가 실행한 대화**를 자체 저장소에 쌓는다(제3자 글). 서브에이전트 계보는 그 안에서 보여 줌. 바깥에서 돌린 기록을 읽는지는 확인 못 함 |
| **레시피 책**: 처음 해 보는 사람에게 검증된 팀 구성을 추천, 무료 사용자도 | 해당 없음 |
| 한국어 우선 | 10개 언어 지원, 한국어 여부는 확인 못 함 |
| 실행하지 않음 | **실행이 본업** |

겹치는 곳은 하나다. **여러 에이전트가 일한 흔적을 보여 주는 것**(위임 계보, 승인 대기). 이 영역에서 T3 Code는 "자기가 실행한 것"을, teamcook은 "어디서 실행했든 남은 기록"을 본다.

**미해결(HANDOFF.md에도 있음):** T3 Code로 실행한 대화가 Claude Code·Codex의 기록 폴더에도 남는지 모른다. 남는다면 우리 업무 일지에 잡히고, 안 남는다면 T3 Code 사용자는 우리 일지로 볼 수 없다. 직접 확인이 필요하다.

## 4. 차용하면 좋은 것

판단 기준은 CLAUDE.md의 원칙이다. ①실행·세션 관리는 안 한다 ②문 두 개(웹=처음 해 보는 사람, 작업실=이미 팀을 돌리는 사람) ③읽기만 한다 ④구독을 그대로 쓴다.

| 순위 | 차용할 것 | T3 Code는 어떻게 | teamcook에서는 | 문 | 크기 | 주의 |
|---|---|---|---|---|---|---|
| 1 | **`npx`로 한 줄 시작** | `npx t3@latest`, brew, winget, 설치 스크립트 | `npx teamcook open` 하나로 작업실을 띄움. 지금은 저장소 받아 `npm install`·`build`·`open` 3단계 | 작업실 | 작음 | **npm에 공개하는 일이라 사용자 결정 필요.** 패키지 이름 `teamcook`이 비었는지 확인, `private: true` 해제 |
| 2 | **권한 감시** | 권한 모드를 고르게 함. 그런데 **기본값이 "전체 접근"** | 역할 파일에 "읽기 전용"이라 적은 팀원이 **실제로 파일을 고쳤는지** 기록으로 확인해 알림. T3 Code가 기본을 느슨하게 둔 곳이 우리의 자리 | 작업실 | 중간 | 기록 형식 의존. "고쳤다"는 기록의 Edit/Write 호출로 판단하므로 100% 정확하다고 말하지 않기 |
| 3 | **측정한 사용량 요약** | 사용량 대시보드, 한도 막대 | 업무 일지의 역할별 토큰·시간을 프로젝트 단위로 모아 보여 줌. **금액은 계산하지 않음**(우리 원칙. T3 Code도 추정이라 못 박음) | 작업실 | 중간 | 미확인 값을 0으로 만들지 않기 |
| 4 | **위임 계보 보기** | 부모-자식 대화를 계보로 보여 줌 | 업무 일지를 "누가 누구에게 맡겼나" 나무로. 이미 위임 기록을 읽고 있어 화면만 바꾸면 됨 | 작업실 | 작음 | — |
| 5 | **프로젝트 고정·숨기기** | 즐겨찾기 고정, 오래된 것 보관 | 최근 프로젝트 목록에서 자주 쓰는 것을 위로, 안 쓰는 것을 숨김 | 작업실 | 작음 | 고정 정보는 브라우저 저장소에만(서버 저장 안 함) |
| 6 | **끝났을 때 알림** | 대화가 끝나거나 승인이 필요할 때 기기 알림 | 실시간 알림 통로(SSE)가 이미 있음. 새 위임이 끝나면 **브라우저 알림** 정도 | 작업실 | 작음 | 휴대폰 푸시·원격은 하지 않음(아래) |
| 7 | **"이미 로그인한 구독을 그대로 쓴다"는 설명** | 토큰을 팔지 않는다는 점을 앞세움 | 우리 원칙 4번과 같음. 소개 화면에서 같은 말로 안심시키기 | 둘 다 | 작음 | — |
| 8 | **성능을 기능으로 취급** | 프레임 하나 떨어져도 버그 | 큰 기록(수백 MB)을 브라우저가 아닌 **도우미에서 읽어 요약만 보냄**. 앞서 실측한 323MB 스캔 1.4초라 가능 | 작업실 | 중간 | — |

## 5. 차용하지 않는 게 좋은 것

| 기능 | 가져오지 않는 이유 |
|---|---|
| 에이전트 **실행, 대기열, 자동 재개, 예약 작업, Workflows, 웹훅** | **"실행·세션 관리는 하지 않는다"가 확정된 결정.** 여기서 T3 Code와 경쟁하면 이긴다고 보기 어렵다. 그쪽이 본업이고 제품 크기가 우리의 몇 배다 |
| 위임(`delegate_task`), 모델 바꾸기, 곁가지 대화, fork | 같은 이유. 단, **"Claude가 계획하고 Codex가 구현"** 같은 조합은 우리 **레시피로 만들 가치**가 있다(실행은 T3 Code·Claude Code가 하고 우리는 조합법을 제공) |
| 자동 실행 버튼, 프롬프트 자동 입력 | 앞서 결정한 대로 **복사까지만** |
| worktree 관리, 커밋·푸시·PR 버튼, 체크포인트·되돌리기 | git을 실행하는 일. 도우미의 "git 실행 없음" 규칙과 충돌. 사고가 나면 사용자 코드를 잃는다 |
| 터미널, 파일 편집기, 내장 브라우저, 시뮬레이터 | IDE 영역. 문 두 개 정리 때 "중구난방"이라고 하신 방향의 반대 |
| 휴대폰 앱, 원격 접속(Tailscale·터널), 서버 계정 | 원격 접속은 **외부에서 내 컴퓨터를 여는 일**이라 도우미의 "이 컴퓨터 안에서만" 안전 규칙을 깬다. 회원가입·서버도 비목표 |
| 비밀값 관리(1Password), API 키 보관 | **API 키를 받거나 저장하지 않는 것**이 원칙 |
| 금액 환산 사용량, "API 환산 비용" | 우리는 토큰·금액 숫자를 짐작하지 않는다. T3 Code도 추정이라 밝힘 |
| 음성 입력, 테마·언어 10개, 텍스트 생성 모델 설정 | 우리 사용자의 문제가 아님 |
| 권한 모드 **기본값을 "전체 접근"으로 두기** | 반대로 해야 한다. 우리는 읽기 전용 같은 제한을 **보여 주는 쪽** |
| 기능을 계속 늘려 따라가기 | T3 Code는 하루 단위로 기능이 늘고 있다(11/21~23 사이 야간 빌드만 십수 개). **기능 수 경쟁은 질 수밖에 없다** |

## 6. 우리의 자리를 어떻게 지킬까

1. **역할 파일을 사람이 이해하는 팀원 카드로 보이게·고치게** — 이번 조사에서 T3 Code에 같은 기능이 있다는 근거를 못 찾았다. 제일 중요한 차별점이다. 다만 **T3 Code가 이걸 만들면 이 차별점은 사라진다.** 계속 지켜볼 일이다.
2. **어디서 실행했든 읽는 업무 일지** — T3 Code는 자기 대화만 안다는 것이 자료에서 읽히는 해석이다(단정은 아님).
3. **레시피 책과 무료 사용자 경로** — T3 Code는 이미 도구를 쓰는 사람이 대상이다. 처음 시작하는 사람을 맞이하는 쪽은 우리다.
4. **느슨한 기본값을 보완하는 쪽** — 권한 감시(위 4장 2번).
5. **함께 쓰는 관계로 포지셔닝** — "T3 Code로 돌리고, 팀을 보고 고치는 것은 teamcook에서." 위의 미해결 항목(T3 Code 대화가 우리 일지에 잡히나)을 확인하면 이 말을 근거 있게 쓸 수 있다.

## 7. 정해야 할 것

1. **`npx teamcook open` 공개 여부.** 가장 효과가 큰 차용인데 바깥에 공개하는 일이다.
2. T3 Code를 실제로 설치해 **① 역할 파일을 어떻게 다루는지 ② 대화가 `~/.claude/projects`·`~/.codex/sessions`에도 남는지**를 확인할지. 이 두 가지가 위 6장 판단을 가장 크게 바꾼다.
3. 4장의 순위대로 만들지, 앞서 논의한 "챗 로그 활동 요약"을 먼저 할지. 활동 요약과 4장 3번(측정한 사용량), 4번(위임 계보)은 같은 기반을 쓴다.
